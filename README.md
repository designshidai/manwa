## 这个仓库是什么

一个**纯静态的地址发布页**：明确告诉读者「漫蛙现在从哪进」，并在主站临时不通时提供可访问的兜底页。

它**不是**内容站，也不承担任何内容分发：

- 不存储、不上传、不分发漫画内容
- 不提供安装包直链，下载一律跳回主站下载页
- 不接入统计、不加载第三方字体或 CDN，全页零外部请求

页面为单个 `index.html`，样式内联，无构建、无依赖、无框架，直接丢到任何静态托管上就能跑。

## 为什么要一个「发布页」

同类站点最常见的困扰不是打不开，而是**找错入口**：搜索结果前排常被搬运站、跳转站与仿冒站占据，它们记录点击、插入广告，甚至诱导安装来路不明的包。

所以这里只做一件事——把唯一入口写清楚，并给出可自行核验的判断依据：

| 看什么 | 正常入口 | 仿冒站常见特征 |
| --- | --- | --- |
| 域名 | `manwa.click` | 多一个字母、换后缀、加连字符 |
| 安装包 | 只在主站下载页提供 | 弹窗塞「高速下载器」、捆绑软件 |
| 页面行为 | 可正常浏览，登录自愿 | 强制跳转、要求付费才能看 |
| 发布方式 | 地址固定，不做「每日更新」 | 天天喊「最新地址已更新」、批量刷短链 |

## 关于「最新地址」的常见误解

- **地址不会按月换。** 主域名长期稳定，无需追着「最新」跑。
- **没有备用域名，也没有镜像站。** 官方不运营备用域名，也未授权任何第三方镜像；自称「官方备用入口」的都是第三方。
- **「2026 年某月最新地址」不是官方口径。** 这类说法多由引流站编造，用于截流与投放广告。
- **打不开 ≠ 站点下线。** 九成是本地缓存、线路或代理问题，先强刷（Ctrl+Shift+R）、换网络、手动输入域名。

## 维护方式

### 换主域名时

`index.html` 内的链接为完整绝对地址。改域名只需在文件内做一次全局替换：

```
https://manwa.click/  →  https://新域名/
```

同时更新三处：

1. `.url` 元素的显示文本与 `#copyBtn` 的 `data-url` 属性（复制按钮取这个值）
2. 页面顶部的「核验时间」文案
3. 本 README 里的入口表

### 新增一个直达入口

复制一段 `.card` 结构到 `.grid` 里，改 `href`、标题、副标题即可，样式自动复用。

### 索引策略

页面默认带 `<meta name="robots" content="noindex,follow">`：发布页只作收藏用的兜底入口，不与主站争同一批关键词排名。

若希望本页被搜索引擎收录，删掉这一行即可；但要注意它容易被判为与主站内容重复的镜像页，通常弊大于利。

## 部署

仓库根目录已是可直接发布的静态站点，任选其一：

**GitHub Pages**

1. 仓库 **Settings → Pages**
2. Source 选 **Deploy from a branch**
3. Branch 选 `main`，目录选 `/ (root)`，保存
4. 约一分钟后就绪：`https://designshidai.github.io/manwa/`

**其它静态托管**：把仓库根目录原样上传即可，无需构建命令，无环境变量。
